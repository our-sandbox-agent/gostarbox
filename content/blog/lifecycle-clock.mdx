原型雖然「假」，但有一塊我們決定認真做：**狀態計時**。因為如果計費模型是「依狀態累計」，那麼時鐘本身就是產品的核心邏輯，值得在原型階段就把 edge case 想清楚。

## 三個必須成立的性質

### 1. 重新整理要接續

使用者重新整理頁面，剩餘的 auto-idle 倒數不應該重來，也不能把關頁期間的時間算進任何狀態。`restoreClock` 的做法是把保存時間點（`accountedAt`）之後的時段整體平移：所有錨點時間（`lastActivity`、`stateSince`）加上「現在減掉保存點」的差值，等效於「這段時間不存在」。

### 2. 關頁期間不計時

承上，這是同一個機制的兩面。瀏覽器分頁被節流、電腦睡眠、直接關頁再開——只要 `accountedAt` 落後於現在，中間的缺口就不會被記入任何狀態的秒數。這對「示意計費」是誠實的：我們只對頁面開著期間負責。（未來真實系統的伺服器端權威時鐘是另一個問題，ADR 裡有討論。）

### 3. 延遲的 tick 要切開結算

背景分頁的 `setInterval` 可能一次被延遲數分鐘。如果一次把延遲的時間全記給當下狀態，會把「其實已經 Idle 的三分鐘」記成 Active——費用直接差四倍。

`advance` 的迴圈每次只前進到**下一個狀態邊界**（auto-idle 或 auto-suspend 的期限），把該段時間記給當下狀態，然後推進狀態、繼續結算，直到追上現在。也就是說：

- 延遲 10 分鐘、其中 2 分鐘後就該降級 → 2 分鐘記給 Active，8 分鐘記給 Idle。
- 期間跨越兩次邊界 → 迴圈跑兩輪，日誌裡會出現兩筆 auto 降級紀錄。

手動切換狀態（`setState`）前也先呼叫 `advance` 結算，確保切換前的時間歸屬正確。

## 為什麼寫成純函式

`lifecycle.js` 不碰 DOM、不碰儲存、不產生副作用——所有函式接收 box 物件與 `now`，回傳修改後的物件。這讓 [生命週期測試](https://github.com/our-sandbox-agent/sandbox-console/blob/main/lifecycle.test.js) 可以直接用假時鐘斷言：

- 重新整理接續剩餘時間
- 關頁期間不計入任何狀態
- 手動 Set idle 後從當下開始完整的 Idle 倒數
- 延遲回呼跨越多個狀態邊界的時間分配
- 切換狀態前的時間結算

未來控制平面實作時計費邏輯不能依賴瀏覽器時鐘，這套語意會原封不動搬去伺服器端的事件帳本（見 usage ledger ADR）。原型的價值之一，就是把這些語意先用測試釘死。

## 限制

這套機制只覆蓋單一分頁。多分頁同時開啟時，兩個分頁各自平移 `accountedAt`，可能重複計時；離線計費、後端權威時鐘也尚未實作。這些都在 README 的限制清單裡，沒有藏。
