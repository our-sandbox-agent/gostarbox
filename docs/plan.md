## 已決定的方向

- Runner 與 CLI 第一版就用 Go，控制平面 TypeScript、前端保留 JavaScript，不安排重寫。[語言 ADR](adr/runner-language.md)
- 第一批是有長任務需求的受邀個人開發者，只支援 Claude 與 API key。Codex／Harness 後移。
- 斷線不停止程序；冷 Suspend 停程序留檔案，恢復啟動新程序並依 session ID 接回對話。暖恢復另做研究。[生命週期 ADR](adr/sandbox-lifecycle.md)
- 先邀 3–5 人受限試用，再補齊完整 Alpha。小規模也有放行驗收，不把熟人當安全措施。
- 沒有預設運行時限；使用者可在建立時或之後自行設定每個沙盒的上限，到期前提醒、可延長，到期冷 Suspend 並明示會中斷執行中的工作。無完成訊號時不自動 Suspend，成本依容量、配額及告警管理。
- 試用先不收費，從真 Runner 開始記錄用量事件。Idle 不等於沒有 CPU 成本，價格尚未定案。
- 介面終端優先：`sandbox claude` 加 tmux 與瀏覽器終端是主線；瀏覽器版 VS Code（code-server）做成每個沙盒可選的「IDE 模式」，#8 有結果後以 #52 spike 決定是否進 M2，不列入受限試用放行條件。
- 資料夾上傳進 MVP 簡單版：打包直傳、固定大小上限、套用 `.env` 等忽略清單，續傳留後面；git clone 仍是第一入口（#20）。
- Stripe 留在 M3，先用帳本記用量；水平擴展只預留介面，受限試用單一 Runner 主機；Codex 可預裝二進位但標「未支援」，憑證與驗收只做 Claude。
- 對外文案保留我們相對 Boat、Agent 37 的差異：依任務完成而非 wall clock 的自動降級、無預設時限、憑證與內網阻擋的放行證據、帶不確定區間的帳本。（2026-09-22）

## 每一步的可見成果

1. **最小 Runner：** 建立、查詢、冷 Suspend、恢復與明確刪除；先證明資源限制與容量守門。
2. **持久化及終端：** workspace 與選定 home 資料跨冷恢復保留；斷線重連同一個尚未停止的 session。
3. **CLI 與登入：** 一行啟動；GitHub 邀請名單限制；授權 API 與單一終端協定。單一 `console.<網域>`，Runner 僅私網。
4. **取回成果：** 公開 repo clone、使用者主動 push、只下載的 `sandbox cp`。push 失敗仍能下載。
5. **自動狀態：** 長任務有保護；CPU 需求／新任務／鍵盤都能恢復 Active；有效完成且沒有未完任務才倒數 Suspend。
6. **試用放行：** 隔離、key 處理、內網阻擋、容量、備份還原和事故處理有證據；對受邀者說清哪些功能未提供。
7. **用量與未來收費：** 先記狀態、資源與不確定區間，再建立可核對的計價與正式收費流程。
